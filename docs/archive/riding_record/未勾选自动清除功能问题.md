# 未勾选自动清除功能问题

> 对应 PRD 安全验收标准：**"Organizer 未勾选的展示选项赛后自动清除"**
>
> 当前状态：✅ **已解决**（2026-06-06 手动验证通过）

---

## 一、问题详细分析

### 1.1 PRD 要求回顾

PRD 明确规定了四条赛后展示的可勾选项：

- **直接公开（无需勾选）：** 完整排名、Organizer 提供的题目
- **Organizer 可勾选：** 训练数据、Organizer 评论、前 N 名 Riding 亮点（Organizer 设置 N 值，默认 3）、Rider 代码

安全验收标准进一步要求：

> **Organizer 未勾选的展示选项赛后自动清除**

这里的"清除"语义是**数据层面的删除/不可恢复**，而非仅仅是前端隐藏。这符合 ARY 的核心理念——"ARY 不持久化私密数据"。

### 1.2 当前实现的防御层级

当前系统有两层防御，但存在一个缺口：

| 层级 | 措施 | 覆盖范围 | 缺口 |
|------|------|---------|------|
| **第 1 层：前端渲染** | `page.tsx` 中 `displayShow*` 条件渲染 | 用户可见的 UI | 数据仍在数据库中，API 直接查询可能绕过 |
| **第 2 层：`publishShowcase`** | 生成时根据 `displayShow*` 决定生成什么 | 新生成的内容 | 仅在 Organizer **重新点击**"生成赛后展示"时生效 |

**核心缺口**：Organizer 可以在不重新执行 `publishShowcase` 的情况下改变主意，而此时已持久化的数据不会自动清除。

### 1.3 受影响的数据和具体场景

```
displayShowTrainingData: false
  ├── Race.trainingDataSummary          ← 保留在 DB，仅在 UI 隐藏
  └── 风险：低（描述性文本，非私密代码）

displayShowOrganizerComment: false
  ├── Race.organizerComment             ← 保留在 DB，仅在 UI 隐藏
  └── 风险：低（Organizer 自己的评论）

displayShowTopHighlights: false
  ├── RidingHighlight (整表)            ← 旧记录不删除
  └── 风险：中（含 excerpt 和 codeSnippet）

displayShowRiderCode: false
  ├── RidingHighlight.codeSnippet       ← 旧记录中的代码片段不删除
  ├── TeamArchive.codeContent           ← 永久保留（归档设计如此）
  └── 风险：高（Rider 代码属于私密数据）
```

最危险的场景：

> **时序**
> 1. Organizer 创建赛事，`displayShowRiderCode: true`
> 2. 比赛结束，点击"生成赛后展示"→ `RidingHighlight` 中写入了代码片段
> 3. Organizer 意识到不应该公开代码，将 `displayShowRiderCode` 改为 `false`
> 4. **不重新点击**"生成赛后展示"
> 5. 结果：旧 `RidingHighlight` 中的 `codeSnippet` 仍然存在，任何人都能通过直接查询数据库或 API 看到

### 1.4 问题根因

当前项目中**没有**一个独立的 Action 来更新赛后展示选项。现有的 `updateRaceAction` 只修改 `taskDescription` 和 `trainingDataSummary`：

```typescript
export async function updateRaceAction(formData: FormData) {
  const user = await requireRole("ORGANIZER");

  await updateRaceContent({
    organizerId: user.id,
    raceId: String(formData.get("raceId") ?? ""),
    taskDescription: String(formData.get("taskDescription") ?? ""),
    trainingDataSummary: String(formData.get("trainingDataSummary") ?? ""),
  });

  revalidatePath("/");
}
```

这意味着 Organizer **根本无法通过 UI 修改赛后展示选项**（只能在创建时的表单中设置）。这本身就是一个 UX 缺失，也解释了为什么"自动清除"没有触发点。

## 二、实施解决方案

### 2.1 总体思路：三级清除机制

设计一个**"三级清除"机制**，确保无论 Organizer 通过什么方式改变展示选项，数据都会被及时清理：

```
Organizer 修改展示选项
        │
        ├── Level 1: 即时清除 (sync) — 本次新增
        │   修改保存后，在 Prisma $transaction 中同步删除不应保留的数据
        │
        ├── Level 2: 重新生成时清除 (idempotent) — 已有，无需改动
        │   publishShowcase 始终 deleteMany + 按当前 displayShow* 设置 createMany
        │
        └── Level 3: 读取时过滤 (defense in depth) — 本次加固
            前端条件渲染作为最后一道防线
```

#### Step 1：新增 `displayOptionsSchema`（`src/lib/validation.ts`）

由于 `createRaceSchema` 含有 `.superRefine()`（ZodEffects 不支持 `.pick()`），先将 `.object({...})` 提取为 `raceBaseSchema`，在此基础上：

```typescript
const raceBaseSchema = z.object({
  // ... 所有字段定义 ...
});

export const createRaceSchema = raceBaseSchema.superRefine(/* 时间线校验 */);

export const displayOptionsSchema = raceBaseSchema
  .pick({
    displayShowTrainingData: true,
    displayShowOrganizerComment: true,
    displayShowTopHighlights: true,
    displayHighlightCount: true,
    displayShowRiderCode: true,
  })
  .extend({
    raceId: z.string().min(1),
  });
```

> **踩坑记录**：最初使用 `createRaceSchema.pick()` 导致编译错误 `".pick() cannot be used on object schemas containing refinements"`，因为 `.superRefine()` 返回 `ZodEffects`，不再支持对象操作方法。解决方式是将底层 `ZodObject` 单独提取。

#### Step 2：新增 `updateRaceDisplayOptions`（`src/lib/services/races.ts`）

核心逻辑：权限校验 → 变更检测（逐个对比旧值→新值，找出 `true → false` 的选项）→ 事务执行（更新选项 + 按需清除）。

```typescript
export async function updateRaceDisplayOptions(input: {
  organizerId: string; raceId: string;
  displayShowTrainingData: boolean;
  displayShowOrganizerComment: boolean;
  displayShowTopHighlights: boolean;
  displayHighlightCount: number;
  displayShowRiderCode: boolean;
}) {
  const race = await prisma.race.findUnique({ where: { id: input.raceId } });
  if (!race || race.organizerId !== input.organizerId) {
    throw new Error("无权修改这场比赛");
  }

  // 变更检测：仅 true → false 时触发清除
  const shouldClearTrainingData = race.displayShowTrainingData && !input.displayShowTrainingData;
  const shouldClearOrganizerComment = race.displayShowOrganizerComment && !input.displayShowOrganizerComment;
  const shouldClearHighlights = race.displayShowTopHighlights && !input.displayShowTopHighlights;
  const shouldClearRiderCode = race.displayShowRiderCode && !input.displayShowRiderCode;

  await prisma.$transaction(async (tx) => {
    // 更新 5 个 display 字段
    await tx.race.update({ where: { id: input.raceId }, data: { /* ... */ } });

    // 按需清除
    if (shouldClearTrainingData)    → Race.trainingDataSummary = ""
    if (shouldClearOrganizerComment) → Race.organizerComment = ""
    if (shouldClearHighlights)       → RidingHighlight.deleteMany
    if (shouldClearRiderCode)        → RidingHighlight.codeSnippet = "Organizer 未公开 Rider 代码。"
                                    → TeamArchive.codeContent = ""
  });
}
```

#### Step 3：新增 `updateDisplayOptionsAction`（`src/app/actions.ts`）

Server Action，负责 `requireRole("ORGANIZER")` 鉴权、从 `FormData` 解析 checkbox 值（`"on"` 表示勾选）和数字字段，调用 `updateRaceDisplayOptions`，最后 `revalidatePath("/")`。

#### Step 4：Organizer Console UI（`src/app/page.tsx`）

在 "榜单与赛后展示" Panel 中，插入展示选项编辑表单：

- 4 个 checkbox（`defaultChecked` 取自 `race.displayShow*` 当前值）：公开训练数据、公开评论、展示 Highlights、公开代码
- 1 个 number input：Highlight 数量（0~20）
- "保存展示选项" 按钮

**交互安全**："公开 Rider 代码" checkbox 从勾选 → 取消勾选时，`onChange` 弹出 `confirm("取消勾选将永久清除已公开的 Rider 代码，确定吗？")`，用户取消则 `e.preventDefault()` 阻止状态变更。

#### Step 5：加固前端渲染（`src/app/_components/ary-shared.tsx`）

作为最后一道防线，`<pre>{highlight.codeSnippet}</pre>` 改为条件渲染：

```tsx
{race.displayShowRiderCode ? (
  <pre>{highlight.codeSnippet}</pre>
) : null}
```

### 2.3 清除语义对照表

| 取消勾选（true→false） | 清除目标 | 清除方式 |
|------------------------|---------|---------|
| `displayShowTrainingData` | `Race.trainingDataSummary` | 设为 `""` |
| `displayShowOrganizerComment` | `Race.organizerComment` | 设为 `""` |
| `displayShowTopHighlights` | `RidingHighlight` 整表 | `deleteMany` |
| `displayShowRiderCode` | `RidingHighlight.codeSnippet` | 设为占位文本 |
| `displayShowRiderCode` | `TeamArchive.codeContent` | 设为 `""` |

### 2.4 三级防御闭合验证

| 层级 | 触发时机 | 实现位置 | 状态 |
|------|---------|---------|:---:|
| Level 1 | Organizer 修改展示选项 | `updateRaceDisplayOptions` → `$transaction` 同步清除 | ✅ |
| Level 2 | Organizer 点击"生成赛后展示" | `publishShowcase` → `deleteMany` + 按当前选项重建 | ✅ |
| Level 3 | 前端渲染 | `ary-shared.tsx` `displayShowRiderCode` 条件控制 + `page.tsx` 状态文本条件 | ✅ |

### 2.5 关于 `TeamArchive` 的特别说明

`TeamArchive` 的设计初衷是"最佳提交归档"，用于赛后展示。当 Organizer 取消 `displayShowRiderCode` 时，**清除 `TeamArchive.codeContent` 但保留其他字段**（分数、agent 类型等）。这样：

- 榜单数据（`LeaderboardEntry`）不受影响——分数排名始终公开（PRD 规定"直接公开无需勾选"）
- Harness 评价（`HarnessEntry`）不受影响——驾驭能力评价基于 reasoning/keyword 分，不依赖代码正文
- 赛后展示中的 Highlights 不受影响——只是 `codeSnippet` 变为占位文本
- 如果 Organizer 改变主意重新勾选并点击"生成赛后展示"：`publishShowcase` 从 `TeamArchive` 中读取 `codeContent`（已清空），因此 `codeSnippet` 为空。代码不可恢复，除非 Runner 重新提交触发新的 `TeamArchive.upsert`

## 四、风险与取舍

| 决策点 | 选择 | 理由 |
|--------|------|------|
| `trainingDataSummary` 清空还是保留？ | 清空 `""` | 训练数据说明属于"Organizer 可勾选"项，取消勾选意味着不应在 ARY 侧保留 |
| `TeamArchive.codeContent` 是否永久删除？ | 清空 `""` | 代码属于 Rider 私密数据，但榜单排名和分数需要保留。折中：保留归档元数据，清除正文 |
| 是否需要"软删除"（可恢复）？ | 不需要 | PRD 明确说"自动清除"，且 Organizer 重新勾选后可通过 `publishShowcase` 重建 |
| 是否需要二次确认？ | 已实现 | "公开 Rider 代码" checkbox 取消勾选时弹出 `confirm` 确认 |
