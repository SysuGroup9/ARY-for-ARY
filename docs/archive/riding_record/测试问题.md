# 问题清单与改进建议

## 1. UI 错误提示缺失

### 问题描述

当前系统在发生错误时，没有友好的 UI 提示页面或弹窗。用户操作失败时看不到明确的错误信息。

### 具体场景

| 场景 | 当前表现 | 期望表现 |
|------|----------|----------|
| 用户名或密码错误 | 无提示或控制台报错 | 弹窗提示“用户名或密码错误” |
| 不在报名时间内尝试报名 | 无提示 | 弹窗提示“当前不在报名时间内” |
| 用户名已存在 | 无提示 | 弹窗提示“用户名已存在，请更换” |

### 改进建议

- 统一使用 Toast 或 Modal 组件展示错误信息
- 后端返回明确的状态码和错误信息，前端捕获后展示

---

## 2. 注册页面多余字段（已解决,2026-06-06重新设计了登录页面）

### 问题描述

注册页面有一个“显示名”字段，但系统实际使用 `username` 作为登录凭证和展示名称，该字段多余。

### 改进建议

- 删除“显示名”字段
- 注册时只需填写：用户名、密码、确认密码、选择角色

---

## 3. 题目上传方式不合理

### 问题描述

当前发布题目时，Organizer 需要手动填写一个 `xxx.zip` 的字符串作为题目压缩包路径，而不是通过文件上传按钮选择本地文件。

### 当前表现
题目压缩包: [________________] (文本框，手动输入路径)

### 期望表现
题目压缩包: [选择文件] 未选择任何文件

### 改进建议

- 使用 `<input type="file" accept=".zip">` 实现本地文件上传
- 后端接收文件后保存到服务器或云存储，返回可访问的 URL
- 数据库存储文件 URL 而非用户输入的字符串

## 4. 比赛期间更正题目的规则

### 问题描述

当前系统支持 Organizer 在比赛期间修改题目描述或训练数据，但修改后的影响未定义。

### 规则定义

当 Organizer 在比赛期间更正题目或训练数据时，应执行以下操作：

| 操作 | 说明 |
|------|------|
| 清空已有提交记录 | 所有队伍的已有提交不再计入排名 |
| 清空进度榜单 | 进度榜单重置，从零开始 |
| 保留队伍信息 | 队伍成员、报名状态不变 |
| 通知所有参赛者 | 发送通知：“题目已更新，请重新提交” |
| 记录更正历史 | 保留更正记录，便于追溯 |

### 数据影响

| 数据 | 是否清空 |
|------|----------|
| 队伍信息 | 否 |
| 报名记录 | 否 |
| 提交记录 | 是 |
| 进度榜单 | 是 |

### 实现建议

- 在 Organizer 修改题目后，自动触发以下逻辑：
  1. 删除该赛事下所有 `submissions` 记录
  2. 重置 `leaderboard_entries` 表
  3. 创建 `race_announcements` 记录，广播通知
  4. 在赛事详情页展示“题目已更新”标识
