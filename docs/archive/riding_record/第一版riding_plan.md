# ARY GRS 001 第一版 Riding Plan  2026-06-03

## 1. 产品定位

ARY（Agent Racing Yard）是一个面向AI Coding Agent竞赛的**评测与展示平台**。

ARY 不负责组内协作，组内通讯、Agent接管、代码导出由 **Dev Compass（DC）** 提供。

## 2. 角色与职责

### 2.1 Dev Compass（DC）

老师开发的协作工具，功能如下：
- 成员授权阅读其他成员的 Riding 记录，在小组对话栏中给出建议
- 成员授权其他成员实时接管其 Agent 进行开发
- 提供接口导出代码和对话上下文

参赛者组内通讯统一使用 DC，参赛者的安全部分无需考虑。

### 2.2 企业

负责提供竞赛的各项内容：
- 竞赛题目、测试数据、训练数据（可选）
- 可选择是否保存参赛队伍的代码和 Riding 记录

### 2.3 ARY

本产品的核心平台，负责：
- 展示企业发布的竞赛题目
- 借助 DC 收集参赛者的代码和 Riding 记录
- 提供评价标准及权重供企业勾选，并根据评价标准给出评分
- 展示榜单（前3名可展示 Riding 亮点）
- 企业可对所有队伍进行赛后评论
- 提供赛后展示标准供企业勾选，决定公开榜单的内容
- 企业可自行获取参赛者的代码和 Riding 记录

### 2.4 参赛者

- 通过 ARY 查看企业发布的竞赛题目
- 通过 DC 进行组内协作
- 提交代码和 Riding 记录

## 3. 数据结构

| 角色 | 数据内容 |
|------|----------|
| 参赛者 | 代码压缩包（.zip）+ 对话记录（.txt） |
| 企业 | 题目压缩包（可含训练数据）+ 评价配置（.json，含任务完成要求、对话关键词） |
| ARY | 展示配置（.json） |

## 4. 安全核心

| 约束 | 实现方式 |
|------|----------|
| 企业测试数据/用例不暴露给参赛者 | 测试数据仅企业内部使用 |
| 企业未勾选的展示选项赛后自动清除 | ARY 根据勾选决定展示内容 |
| 企业可一键清除比赛 | 提供“清除比赛”按钮 |
| 企业可选择是否保存参赛者代码和 Riding 记录 | 创建赛事时勾选 |
| 企业发布题目时可勾选是否有训练集，ARY 不保存训练集 | 企业勾选后 ARY 不处理 |

## 5. 赛后展示选项（企业勾选）

| 选项 | 说明 |
|------|------|
| 企业提供的题目 | 是否在赛后公开题目 |
| 训练数据 | 是否在赛后公开训练数据 |
| 企业评论 | 是否在赛后公开企业评论 |
| 前3名Riding亮点 | 是否展示前3名的Riding过程亮点 |
| 参赛者代码 | 是否公开参赛者代码 |

## 6. 后续优化（S1已完成）

- 企业在比赛期间可更正题目或数据（一般需要加时），原排名全部清空

## 7. 超出S1范围的功能（留待未来更新）

- 组队功能（小组管理）
- Reviewer/Contributor 角色
- Agent 给出每个参赛队伍建议
