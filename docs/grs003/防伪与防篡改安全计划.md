# 1. 文档定位

本文定义 ARY MVP 在 GRS003 语义下的防伪与防篡改方案，目标不是把安全子系统做成独立产品，而是为以下链路建立可信边界：

- 用户身份与角色边界
- RaceProject / CAConnection / Session 的实时接入边界
- Work 与外部代码材料的完整性边界
- Projection、Evidence、Report 的可追溯边界
- Organizer / Judge 在评审前看到的风险提示边界
- Runner 在材料校验、摘要生成与结构化预处理链路中的完整性边界

本文明确保留 Runner，但 Runner 只作为内部辅助处理组件，不再作为领域中心、评审主体或裁决来源。正式评审与结果裁决仍留在受权限控制的 Organizer / Judge 工作流中。

---

# 2. 背景与目标

GRS003 的安全重点不是“把所有异常自动打成 DQ”，而是：

1. 防止未登记、未握手、归属错误或被篡改的数据进入有效证据链。
2. 防止 Work、代码材料、题目材料、评审辅助输入在传输或存储过程中被静默篡改。
3. 让实时 CA 接入、作品材料、Runner 辅助处理结果都具备可追溯性。
4. 在正式评审前向 Organizer / Judge 暴露风险、证据缺口和可信度问题。
5. 让大屏、Live Hall、Race Console 读取 Projection 或已发布结果，而不是直接读取未经校验的原始输入。

安全目标与 GRS003 产品约束保持一致：

- 实时 CA 数据是骑行过程证据、Projection 输入和评审参考，不是参赛资格硬门禁。
- CA 接入失败、无 CA 数据、证据缺口或高风险不自动取消 Registration 的提交、评审或 Award 资格。
- 系统需要产生 Review Flag / Review Readiness，而不是直接用安全检测替代人工评审。

# 3. 保护对象

| 对象 | 为什么要保护 |
|---|---|
| User / GitHub 登录态 | 防止身份伪造、越权访问后台 |
| Registration | 防止参赛身份被冒用或错误绑定 |
| RaceProject | 防止把错误来源的数据混入某个选手的比赛事实 |
| CAConnection | 防止未登记 CA、错误 connector、错误外部项目伪装成有效接入 |
| Session / Riding Signal | 防止消息伪造、重放、串线和篡改 |
| Work / GitHub Repo / 外部材料 | 防止作品材料被替换、篡改或错误归属 |
| Race challenge materials | 防止赛题、数据包、评测输入被未授权修改 |
| Evidence | 防止失去来源引用与可信度标记 |
| Projection | 防止将异常输入直接传播到公开展示 |
| Report | 防止不可信摘要进入评审总结或选手报告 |
| Runner 输入输出 | 防止 Runner 拿到被篡改材料，或输出无法追溯 |

# 4. 威胁模型

| 威胁 | 描述 | 主要影响 |
|---|---|---|
| 身份伪造 | 冒充其他 Rider、Organizer、Judge 或 CA connector | 越权、错误归属 |
| CA 伪接入 | 未登记或未握手的 CAConnection 推送数据 | 污染比赛事实 |
| 消息篡改 | Riding signal 在链路中被修改 | Projection / Evidence 失真 |
| 消息重放 | 重复发送旧消息或旧快照 | 制造假活跃度、假进度 |
| 归属串线 | 某个外部 CA Project / Session 被错误绑定到其他 Registration | 证据归属错误 |
| 作品篡改 | Work、Repo、压缩包、Demo 材料被静默替换 | 评审对象失真 |
| 题目篡改 | 赛题或评测输入被未授权修改 | 比赛公平性受损 |
| Runner 输入污染 | Runner 拉取到的代码、材料或摘要输入已被篡改 | 评测和摘要失真 |
| Runner 输出伪造 | Runner 产出的摘要、校验结果、指标来源不清 | 无法信任报告链路 |
| 公开泄露 | 原始 Session、私有 Evidence、未发布结果被公开读取 | 隐私和比赛秩序受损 |

# 5. 安全原则

## 5.1 先校验归属，再接收数据

任何进入有效链路的实时 CA 数据，都必须先满足：

- 对应 Rider 已拥有该 Race 的 approved Registration。
- 该 Registration 已幂等生成唯一 RaceProject。
- `caConnectionId` 已登记并完成握手。
- `caConnectionId` 归属当前 `raceProjectId`。
- connector 未被禁用，来源未被吊销。

未满足以上条件的数据，不得进入有效 Projection、Evidence 或 Report 输入，只能拒收或写入隔离审计区。

## 5.2 Projection 不是事实源

大屏、Live Hall、过程榜单和 Race Console 的过程展示优先读取 Projection。Projection 可以重算，也必须允许丢弃异常输入后重建。

## 5.3 风险提示优先于自动处罚

安全检测的默认输出应是：

- review flags
- readiness 状态
- evidence completeness
- integrity 状态
- 审计记录

只有当主办方另有赛事规则明确授权时，才可在人工作业流中执行取消资格、移除榜单或隐藏作品等动作；本文不把自动 DQ 作为默认系统行为。

## 5.4 原始数据最小暴露

Public Site、Live Hall、Screen Console 不读取原始 Session。公开端只读取：

- Projection
- Evidence 摘要
- 已公开 Work
- 已发布 Award
- 已发布且公开可见的 Report

## 5.5 Runner 服从同一可信链

Runner 不是独立真相源，而是消费 ARY 已校验材料、执行辅助校验、摘要生成或结构化预处理的内部组件。Runner 的输入、输出、版本和校验结果都需要可追溯；Judge / Organizer 才是正式评审意见与结果裁决的主体。

# 6. 可信链设计

## 6.1 身份与访问层

- 账号入口使用 GitHub 登录。
- 后台访问必须经过登录和 `User.roles` 权限校验。
- Race Console、Admin Console、Screen Console 的访问边界隔离。
- Organizer、Judge、Rider 只读取各自范围内的数据与摘要。

这部分主要解决“人是谁、是否有权限看到或操作该资源”的问题。

## 6.2 CAConnection 登记与握手层

每个参赛 CA 必须先形成 CAConnection，再进入实时接入。

登记记录至少需要包含：

- `registrationId`
- `raceProjectId`
- `caConnectionId`
- `caType`
- `connectorId`
- `connectorVersion`
- `caProjectId`
- `registeredAt`
- `ingestionStatus`
- `credentialFingerprint` 或等价来源标识

握手完成后，ARY 才接受该 CAConnection 的实时消息或快照抓取请求。

## 6.3 实时消息接入层

对于 push 到 ARY 的 RidingSignalMessage 或等价消息：

- 校验 `caConnectionId` 是否已登记且归属正确。
- 校验消息 schemaVersion、messageId、idempotencyKey。
- 对签名或来源令牌进行校验。
- 对时间戳窗口进行合理性检查。
- 对同一 `caConnectionId + caSessionId + sequence` 做幂等去重。
- 对异常来源、重复消息、乱序严重消息做隔离审计。

说明：

- “时间戳超时”默认是接入风险，不直接等价为作弊。
- 反馈类说明消息、网络抖动或 connector 重试需要与恶意重放区别处理。

## 6.4 Session 快照抓取层

ARY 需要完整 Session 时，从已登记 connector 提供的 HTTP fetch 接口抓取。

要求：

- fetch 目标必须绑定到已登记 CAConnection。
- 响应应带来源标识、抓取时间、外部 session 标识和摘要校验信息。
- 抓取失败只形成接入异常或证据缺口，不自动改变 Registration 资格状态。

## 6.5 Work / 代码材料完整性层

Work、GitHub Repo、压缩包、Demo 附件等材料进入系统时，需要建立完整性元数据：

- sourceRef
- 内容哈希
- 上传或抓取时间
- 提交人 / 触发人
- 所属 Registration / Work
- 可见性

这确保后续评审、Evidence 引用和 Runner 拉取时使用的是同一份可追溯材料。

## 6.6 题目与评测输入完整性层

主办方维护的 challenge materials、数据包、评测配置和输入样例，应记录：

- 版本号
- 内容哈希
- 修改人
- 修改时间
- 修改原因

任何对题目或评测输入的更新，都必须留下审计记录，避免赛中无痕改题或无痕替换评测输入。

## 6.7 Runner 辅助处理层

Runner 可保留并承担以下职责：

- 拉取已锁定或已提交的 Work / 代码材料
- 校验 ARY 提供的内容哈希
- 执行静态检查、摘要提取、结构化分析或其他评审辅助处理
- 输出可回写到 Evidence / Projection / Report 的辅助处理结果

Runner 必须遵守以下边界：

- 不直接接收未登记 CA 的原始消息作为真相源。
- 不直接充当 Judge，也不直接决定 Registration 是否取消资格、是否得奖或最终评分。
- 不绕过 ARY 的权限和归属规则。
- 输出结果必须包含 `runnerVersion`、输入材料引用、输入哈希、处理时间和处理状态。
- Runner 输出默认只作为 Organizer / Judge 的辅助输入，而不是正式裁决本身。

# 7. 检测与处置模型

## 7.1 事件分级

安全相关事件建议分为四类：

| 级别 | 含义 | 默认系统行为 |
|---|---|---|
| reject | 本次输入不接受 | 拒收，不进入有效链路，写审计 |
| risk | 可疑或异常，但不确定是作弊 | 生成 Review Flag / 风险提示 |
| integrity_gap | 证据缺口或可信度不足 | 标记 Evidence / Projection / Report 可信度 |
| confirmed_violation | 经规则或人工确认的违规 | 记录违规结果，交由 Organizer 流程处理 |

## 7.2 典型检测规则

### A. 必须拒收的情况

- `caConnectionId` 未登记
- `caConnectionId` 归属错误 RaceProject
- 握手未完成却发送有效比赛消息
- 签名或来源令牌验证失败
- 幂等键与消息体关键字段冲突

默认处置：

- 拒收本次输入
- 写入审计日志
- 如持续出现，升级为 risk

### B. 形成风险提示的情况

- 同一 CAConnection 高频时间戳异常
- 同一外部 session 在短时间内跨多个 Registration 出现
- Session 活跃但长期无可解释进展
- Work 材料与历史引用差异异常
- Runner 多次拉取哈希不一致
- Runner 辅助摘要与人工评审观察长期明显冲突

默认处置：

- 生成 Review Flag
- 在 Organizer / Judge 视图提示
- 允许人工查看证据摘要与处理历史

### C. 形成证据缺口的情况

- 没有任何 CAConnection
- CAConnection 已登记但始终无有效 Session
- Session 摘要抓取失败
- Work 缺少必要材料
- Runner 处理失败，未能产出可用摘要或验证结果

默认处置：

- 标记 `reviewReadiness` 降级
- 标记 `evidenceCompleteness` 不完整
- 允许继续提交和评审，但明确提醒可信度边界

### D. 可能进入确认违规流程的情况

- 经核实存在身份冒用
- 经核实存在故意篡改提交内容
- 经核实存在恶意串线接入他人 RaceProject
- 经核实存在伪造来源材料或伪造报告输入

默认处置：

- 记录 confirmed violation
- 由 Organizer / Admin 按赛事规则决定是否隐藏展示、撤销结果、取消资格或补充公示

# 8. 与 Projection、Live Hall、Jumbotron 的关系

## 8.1 公开展示使用什么数据

Live Hall、Jumbotron、Billboard 读取的是 Projection，不直接读取原始安全事件流。

Projection 中可以包含有限安全态字段，例如：

- `integrityStatus`: ok / warning / blocked
- `evidenceCompleteness`: complete / partial / missing
- `reviewFlagsCount`
- `connectionHealth`: ok / partial_failed / all_failed

## 8.2 默认展示语义

大屏和实况页默认展示“风险 / 异常 / 接入状态”，而不是直接展示“DQ”。

例如：

- “接入异常”
- “证据缺口”
- “待人工确认”
- “高风险，请评审关注”

只有在 Organizer 明确发布处罚结论后，Projection 才可以同步已发布的处罚状态。

## 8.3 为什么不默认自动 DQ

原因：

- GRS003 明确要求 CA 接入失败和无 CA 数据不自动取消资格。
- Projection 是展示数据，不是最终裁决源。
- 安全检测会产生误报，必须保留人工复核空间。

# 10. 接口与流程要求

## 10.1 CAConnection 登记

登记接口至少应写入：

- Registration / RaceProject 归属
- connector 与 CA 类型信息
- 外部 CA Project 标识
- 凭证指纹或来源标识
- 当前状态

## 10.2 握手与实时消息接收

接收消息前必须完成：

1. 连接归属校验
2. 凭证校验
3. 幂等校验
4. 基本时间有效性检查
5. 审计记录

## 10.3 Work / 材料提交

提交或抓取作品材料时必须：

1. 固定 owner（Registration / Work）
2. 记录 sourceRef
3. 计算内容哈希
4. 记录可见性
5. 允许后续 Runner 和 Evidence 引用同一哈希记录

## 10.4 Runner 拉取与回写

Runner 处理前：

1. 拉取已锁定输入
2. 校验输入哈希
3. 记录本次执行上下文

Runner 回写后：

1. 回写结构化结果、摘要或其他评审辅助结果
2. 记录输出哈希
3. 记录版本与状态
4. 如失败，标记为 integrity gap 或 processing failure，而不是直接改写比赛资格
5. 回写结果默认进入 Organizer / Judge 可见的辅助信息层，不直接替代正式评审意见或最终裁决

# 11. 非功能要求

## 11.1 传输安全

- 所有外部通信使用 TLS。
- connector 与 ARY、Runner 与 ARY 的内部通信也应使用受控安全链路。

## 11.2 可观测性

至少可追踪：

- CAConnection 握手状态
- 消息拒收数量与原因
- Session fetch 成功率
- 完整性校验失败次数
- Runner 输入校验失败次数
- Review Flag 产生、确认、关闭流程

## 11.3 可恢复性

- Projection 可重建。
- 安全审计事件保留独立记录，不依赖 Projection 存活。
- Runner 执行失败后允许重跑。
- 单个 RaceProject 的接入异常不应导致整个赛事公开展示不可用。

## 11.4 隐私与最小披露

- 原始 Session 默认不公开。
- 审计事件默认只对 Organizer / Admin 可见。
- Judge 默认只看到评审所需的摘要与风险提示。
- Public 不可见未发布处罚结论、原始证据和私有审计细节。

# 12. 实施优先级

## P0

- GitHub 登录与后台角色校验收口
- CAConnection 登记、握手、归属校验
- 实时消息幂等与拒收审计
- Work / 材料哈希记录
- Runner 输入哈希校验
- Review Flag 基础模型
- Organizer / Judge 对 Runner 辅助结果的查看与引用边界

## P1

- Session fetch 校验与失败归因
- Projection 可信度字段
- Race Console 中的风险提示与 readiness 展示
- Screen Console / Live Hall 的有限风险态透出
- 题目材料审计与版本追踪

## P2

- 凭证轮换与吊销
- 更细的 connector 风险画像
- Runner 输出签名或更强输出校验
- Organizer 处罚发布工作流与公开公示联动

# 13. 验收标准

满足以下条件时，可认为本计划达到 MVP 可用基线：

- 未登记、未握手、归属错误的 CAConnection 数据无法进入有效 Projection、Evidence 或 Report 输入。
- 实时消息支持幂等去重，并保留拒收审计。
- Work / 外部代码材料 / Runner 输入具备可追溯哈希记录。
- Runner 在处理前校验输入完整性，处理后记录版本、状态与输出引用。
- Runner 输出只作为 Organizer / Judge 的辅助输入，不直接替代正式评审意见或最终裁决。
- 系统能够生成 review flags、integrity status、evidence completeness 等评审前风险提示。
- CA 接入失败、无 CA 数据、Runner 失败不会自动取消 Registration 的提交、评审或 Award 资格。
- Live Hall 与 Jumbotron 只读取 Projection 或已发布结果，不直接读取未经校验的原始输入。
- Organizer / Judge 可以看到与评审相关的风险提示，但 Public 无法读取私有审计细节。

---

# 14. 一句话总结

在 GRS003 里，防伪与防篡改的目标不是把 Runner 或安全规则做成“自动裁判”，而是让 Registration、RaceProject、CAConnection、Work、Evidence、Projection、Report 这条链路中的每一步都可验证、可追溯、可提示风险，并把最终裁决留在受权限控制的 Organizer / Judge 工作流中。
