## 三、关键证据记录

### 证据 A：测试策略设计——从"点页面"到"链路闭环"

#### 整体概括

GRS004 交付前，我没有采用"逐个页面点一遍看是否报错"的朴素测试方式，而是先梳理出四层验证框架，然后按层递进执行。这个策略让测试效率大幅提升，也让我能在有限时间内覆盖更多边界场景。

#### 四层验证框架

| 层级 | 验证目标 | 典型检查项 |
|---|---|---|
| 第一层：权限边界 | 各角色只能访问对应入口 | Rider 不能看其他 Rider 的 CA 连接；PENDING 成员不能看队内任务 |
| 第二层：数据链路 | 从报名到赛果的数据不断裂 | Registration → RaceProject → CAConnection → Session → Evidence → Projection |
| 第三层：状态流转 | 8 阶段状态机 + 双审批流程 | draft→published→registration→running→submitting→judging→completed→archived |
| 第四层：错误闭环 | 所有失败场景有友好提示 | 登录失败、报名被拒、CA 接入失败、作品提交不完整 |

#### 体现的驾驭能力

这个框架的核心价值不在于"测了多少个页面"，而在于**把零散的功能点组织成有逻辑的验证路径**。Agent 生成的测试覆盖了正常路径，但我的职责是补充 Agent 容易遗漏的边界场景——比如"Team 达到 5 人上限后第 6 人加入""Leader 报名被拒后 Team 是否正确删除""PENDING 成员能否绕过前端直接调 API"。

### 证据 B：E2E 回归中的隐性缺陷定位

#### 整体概括

在执行 35 项 E2E 回归测试时，我没有停留在"✅ 通过 / ❌ 失败"的二分判断上，而是对每条通过项追问"这个通过是否真实覆盖了目标场景"。

#### 关键发现

1. **PENDING 成员访问控制（Phase 9）**

   E2E 脚本中 `rider_eve` 被标记为"Pathfinders Alpha PENDING 成员"，但我在审查种子数据时发现 `rider_eve` 实际属于 **Graph Explorers** 而非 Pathfinders Alpha。这导致测试虽然通过了（PENDING 成员确实被拦截），但拦截原因是"非队内成员"而非"入队申请尚未通过"——两种拦截逻辑不同，后者才是需要验证的业务规则。

   我推动 Agent 修正了测试文档中的描述，并在 TEST-CHECKLIST.md 中明确标注了两支队伍的完整成员状态。

2. **知识库 ZIP 下载权限分层**

   E2E Phase 6 验证了"无关团队代码 API 拒绝访问"返回 403，但我追问了一个更深的问题：**Organizer 是否能下载非自己管理赛事的 Team 代码？** 这个场景在 E2E 中没有覆盖。我推动 Agent 在 `canAccessKnowledgeBase` 中确认了三层权限：member / organizer / admin，并在 TEST-CHECKLIST.md 的手工验收清单中新增了 B9 项。

3. **generateAttentionItems 去重隐患**

   在审查阮依成的骑行记录时，我注意到他提到"Attention Items 可能生成重复条目，去重是下一步优化"。我没有把这个当作"已知问题"跳过，而是推动 Agent 写了 4 项回归测试：
   - 多成员 CA 失败不重复生成
   - CA 接入失败 + 会话风险生成两条独立条目
   - low/none riskLevel 不生成条目
   - 反作弊扣分文案含数值

   这 4 项测试全部通过，确认了当前的按 Team 维度聚合逻辑不会产生重复。

## 六、个人反思

这次项目让我深刻认识到：**测试审查的核心能力不是"写测试用例"，而是"识别哪些场景没有被测到"**。

Agent 生成的测试天然偏向"正常路径"——因为它理解的是需求文档描述的流程。而真正出问题的往往是边界、异常和跨模块交互。我的价值在于：

1. **从他人记录中提取风险**：阮依成提到的"Attention Items 去重"隐患，被我转化为 4 项回归测试。
2. **从种子数据中找语义错误**：`rider_eve` 的队伍归属错误，虽不影响测试通过，但导致验证的不是目标业务规则。
3. **从"E2E 通过"中追问"是否真覆盖"**：35 项 E2E 全通过，但 Race 生命周期完全没 E2E——通过率 100% 不等于覆盖完整。

如果后续继续完善，我会优先推动三件事：
- 修复种子数据的 Prisma ORM bug，让 ca-rotation-disable 3 项测试恢复通过
- 补充 CA 接入端到端 E2E（handshake → push signal → projection → screen）
- 把 `ignoreBuildErrors` 关掉，全量修复 Team 迁移遗留的类型错误
