# 未勾选自动清除功能问题

> 对应 PRD 安全验收标准：**"Organizer 未勾选的展示选项赛后自动清除"**
>
> 当前状态：⚠️ **部分实现** → 修复后：✅

---

## 一、问题详细分析

### 1.1 PRD 要求回顾

PRD 明确规定了四条赛后展示的可勾选项：

- **直接公开（无需勾选）：** 完整排名、Organizer 提供的题目
- **Organizer 可勾选：** 训练数据、Organizer 评论、前 N 名 Riding 亮点（Organizer 设置 N 值，默认 3）、Rider 代码

安全验收标准进一步要求：

> **Organizer 未勾选的展示选项赛后自动清除**

这里的"清除"语义是**数据层面的删除/不可恢复**，而非仅仅是前端隐藏。这符合 ARY 的核心理念——"ARY 不持久化私密数据"。

### 1.2 当前实现的防御层级

当前系统有两层防御，但存在一个缺口：

| 层级 | 措施 | 覆盖范围 | 缺口 |
|------|------|---------|------|
| **第 1 层：前端渲染** | `page.tsx` 中 `displayShow*` 条件渲染 | 用户可见的 UI | 数据仍在数据库中，API 直接查询可能绕过 |
| **第 2 层：`publishShowcase`** | 生成时根据 `displayShow*` 决定生成什么 | 新生成的内容 | 仅在 Organizer **重新点击**"生成赛后展示"时生效 |

**核心缺口**：Organizer 可以在不重新执行 `publishShowcase` 的情况下改变主意，而此时已持久化的数据不会自动清除。

### 1.3 受影响的数据和具体场景

```
displayShowTrainingData: false
  ├── Race.trainingDataSummary          ← 保留在 DB，仅在 UI 隐藏
  └── 风险：低（描述性文本，非私密代码）

displayShowOrganizerComment: false
  ├── Race.organizerComment             ← 保留在 DB，仅在 UI 隐藏
  └── 风险：低（Organizer 自己的评论）

displayShowTopHighlights: false
  ├── RidingHighlight (整表)            ← 旧记录不删除
  └── 风险：中（含 excerpt 和 codeSnippet）

displayShowRiderCode: false
  ├── RidingHighlight.codeSnippet       ← 旧记录中的代码片段不删除
  ├── TeamArchive.codeContent           ← 永久保留（归档设计如此）
  └── 风险：高（Rider 代码属于私密数据）
```

最危险的场景：

> **时序**
> 1. Organizer 创建赛事，`displayShowRiderCode: true`
> 2. 比赛结束，点击"生成赛后展示"→ `RidingHighlight` 中写入了代码片段
> 3. Organizer 意识到不应该公开代码，将 `displayShowRiderCode` 改为 `false`
> 4. **不重新点击**"生成赛后展示"
> 5. 结果：旧 `RidingHighlight` 中的 `codeSnippet` 仍然存在，任何人都能通过直接查询数据库或 API 看到

### 1.4 问题根因

当前项目中**没有**一个独立的 Action 来更新赛后展示选项。现有的 `updateRaceAction` 只修改 `taskDescription` 和 `trainingDataSummary`：

```typescript
export async function updateRaceAction(formData: FormData) {
  const user = await requireRole("ORGANIZER");

  await updateRaceContent({
    organizerId: user.id,
    raceId: String(formData.get("raceId") ?? ""),
    taskDescription: String(formData.get("taskDescription") ?? ""),
    trainingDataSummary: String(formData.get("trainingDataSummary") ?? ""),
  });

  revalidatePath("/");
}
```

这意味着 Organizer **根本无法通过 UI 修改赛后展示选项**（只能在创建时的表单中设置）。这本身就是一个 UX 缺失，也解释了为什么"自动清除"没有触发点。

---

## 二、解决方案草案

### 2.1 总体思路

设计一个**"三级清除"机制**，确保无论 Organizer 通过什么方式改变展示选项，数据都会被及时清理：

```
Organizer 修改展示选项
        │
        ├── Level 1: 即时清除 (sync)
        │   修改保存后，立即删除不应保留的数据
        │
        ├── Level 2: 重新生成时清除 (idempotent)
        │   publishShowcase 始终 deleteMany + 按当前设置 createMany
        │
        └── Level 3: 读取时过滤 (defense in depth)
            前端条件渲染作为最后一道防线
```

Level 2 和 Level 3 **已经实现**，只需补充 Level 1。

### 2.2 具体改动

#### Step 1：新增 Service 函数 — `updateRaceDisplayOptions`

在 `src/lib/services/races.ts` 中新增：

```typescript
// 赛后展示选项的 Zod Schema
import { z } from "zod";

const displayOptionsSchema = z.object({
  raceId: z.string().min(1),
  displayShowTrainingData: z.boolean(),
  displayShowOrganizerComment: z.boolean(),
  displayShowTopHighlights: z.boolean(),
  displayHighlightCount: z.coerce.number().int().min(0).max(20),
  displayShowRiderCode: z.boolean(),
});

export async function updateRaceDisplayOptions(input: {
  organizerId: string;
  raceId: string;
  displayShowTrainingData: boolean;
  displayShowOrganizerComment: boolean;
  displayShowTopHighlights: boolean;
  displayHighlightCount: number;
  displayShowRiderCode: boolean;
}) {
  // 1. 权限校验
  const race = await prisma.race.findUnique({
    where: { id: input.raceId },
  });

  if (!race || race.organizerId !== input.organizerId) {
    throw new Error("无权修改这场比赛");
  }

  // 2. 检测哪些选项从 true → false（需要清除数据）
  const shouldClearTrainingData =
    race.displayShowTrainingData && !input.displayShowTrainingData;
  const shouldClearOrganizerComment =
    race.displayShowOrganizerComment && !input.displayShowOrganizerComment;
  const shouldClearHighlights =
    race.displayShowTopHighlights && !input.displayShowTopHighlights;
  const shouldClearRiderCode =
    race.displayShowRiderCode && !input.displayShowRiderCode;

  // 3. 在事务中：更新选项 + 清除数据
  await prisma.$transaction(async (tx) => {
    // 3a. 更新赛事选项
    await tx.race.update({
      where: { id: input.raceId },
      data: {
        displayShowTrainingData: input.displayShowTrainingData,
        displayShowOrganizerComment: input.displayShowOrganizerComment,
        displayShowTopHighlights: input.displayShowTopHighlights,
        displayHighlightCount: input.displayHighlightCount,
        displayShowRiderCode: input.displayShowRiderCode,
      },
    });

    // 3b. 按需清除数据
    if (shouldClearTrainingData) {
      await tx.race.update({
        where: { id: input.raceId },
        data: { trainingDataSummary: "" },
      });
    }

    if (shouldClearOrganizerComment) {
      await tx.race.update({
        where: { id: input.raceId },
        data: { organizerComment: "" },
      });
    }

    if (shouldClearHighlights) {
      await tx.ridingHighlight.deleteMany({
        where: { raceId: input.raceId },
      });
    }

    if (shouldClearRiderCode) {
      // 清除 RidingHighlight 中的代码片段
      await tx.ridingHighlight.updateMany({
        where: { raceId: input.raceId },
        data: { codeSnippet: "Organizer 未公开 Rider 代码。" },
      });

      // 清除 TeamArchive 中的代码内容
      await tx.teamArchive.updateMany({
        where: { raceId: input.raceId },
        data: { codeContent: "" },
      });
    }
  });
}
```

#### Step 2：新增 Server Action

在 `src/app/actions.ts` 中新增：

```typescript
export async function updateDisplayOptionsAction(formData: FormData) {
  const user = await requireRole("ORGANIZER");

  await updateRaceDisplayOptions({
    organizerId: user.id,
    raceId: String(formData.get("raceId") ?? ""),
    displayShowTrainingData: formData.get("displayShowTrainingData") === "on",
    displayShowOrganizerComment: formData.get("displayShowOrganizerComment") === "on",
    displayShowTopHighlights: formData.get("displayShowTopHighlights") === "on",
    displayHighlightCount: Number(formData.get("displayHighlightCount") ?? 3),
    displayShowRiderCode: formData.get("displayShowRiderCode") === "on",
  });

  revalidatePath("/");
}
```

### 2.3 清除语义对照表

| 选项取消勾选（true→false） | 清除的数据 | 清除方式 |
|---|---|---|
| `displayShowTrainingData` | `Race.trainingDataSummary` | 设为空字符串 `""` |
| `displayShowOrganizerComment` | `Race.organizerComment` | 设为空字符串 `""` |
| `displayShowTopHighlights` | `RidingHighlight` 整表 | `deleteMany` |
| `displayShowRiderCode` | `RidingHighlight.codeSnippet` | 更新为占位文本 |
| `displayShowRiderCode` | `TeamArchive.codeContent` | 设为空字符串 `""` |

### 2.4 关于 `TeamArchive` 的特别说明

`TeamArchive` 的设计初衷是"最佳提交归档"，用于赛后展示。当 Organizer 勾选 `displayShowRiderCode: false` 时，方案建议**清除 `TeamArchive.codeContent` 但保留其他字段**（如分数、agent 类型等）。这样：

- 榜单数据（`LeaderboardEntry`）不受影响——分数排名始终公开（PRD 规定"直接公开无需勾选"）
- Harness 评价（`HarnessEntry`）不受影响——驾驭能力评价基于 reasoning/keyword 分，不依赖代码正文
- 赛后展示中的 Highlights 不受影响——只是 `codeSnippet` 变为占位文本

## 四、风险与取舍

| 决策点 | 选择 | 理由 |
|--------|------|------|
| `trainingDataSummary` 清空还是保留？ | 清空 `""` | 训练数据说明属于"Organizer 可勾选"项，取消勾选意味着不应在 ARY 侧保留 |
| `TeamArchive.codeContent` 是否永久删除？ | 清空 `""` | 代码属于 Rider 私密数据，但**榜单排名和分数需要保留**。折中方案：保留归档元数据，清除正文 |
| 是否需要"软删除"（可恢复）？ | 不需要 | PRD 明确说"自动清除"，且 Organizer 重新勾选后可通过 `publishShowcase` 从 `Submission`（若未清除）或重新提交重新生成 |
| 是否需要二次确认？ | 建议加 | 清除代码内容是不可逆操作，应在 UI 上加 `confirm("取消勾选将清除已公开的代码内容，确定吗？")` |
