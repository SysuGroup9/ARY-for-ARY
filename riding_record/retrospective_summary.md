## 2. Agent 表现分析

### 2.1 Agent 擅长的工作

**算法实现：**
TrackRuntime 的 Catmull-Rom 样条 + 弧长参数化是本次最复杂的算法实现。Agent 一次性给出了正确的实现，包括：
- 样条插值系数计算
- 均匀弧长采样（500 分段）
- 切线向量归一化
- 法向量推导（逆时针旋转 90°）
- `getPathD()` SVG 路径生成

整个 track-runtime.ts 在第一次实现后无需修改（唯一例外是后来的控制点数据，那是数据问题而非算法问题）。

**多文件联动：**
每次需要跨层修改（Prisma → Zod → Service → Form → Component → Jumbotron），Agent 能正确识别所有受影响文件并逐一修改，未出现遗漏链路的情况。

**Bug 诊断：**
裂缝问题（I-02）的诊断比较典型——Agent 能够准确定位抗锯齿 1px 间隙的根因，并给出工程上更优的 SVG mask 解决方案，而不是简单地调整颜色或透明度来掩盖问题。

### 2.2 Agent 不擅长的工作

**视觉感知：**
Agent 无法判断"土黄色赛道放在看台背景上是否好看"，也无法预判"边距 320px 是否会压到看台"。这类感知判断必须通过人工实际查看页面才能获得。

建议：在提供 Agent 视觉类任务时，始终附上参考截图或明确的色号/尺寸规格，减少 Agent 自行发挥的空间。

**跨文件一致性（数据层面）：**
当同类数据在多处存在时（如控制点在 JSON 和 TypeScript 中各有一份），Agent 倾向于各自独立生成而不会自动建立"读取 JSON 文件"的引用关系。

建议：在任务 prompt 中明确要求"单一来源"，例如："Calibrator 的预设控制点必须从 track.profile.json 读取，不得硬编码"。

**可用性细节：**
字号、间距、按钮大小等可用性细节 Agent 生成的默认值往往偏小（符合"紧凑"的默认审美），需要人工在真实设备上体验后反馈。

## 3. 人工判断的核心价值

本次开发中，人的判断在以下方面起到了关键作用：

### 3.1 产品方向锚定

"进度和质量严格分离"这一数据模型核心原则，是人工在阅读 PRD 后确立的，Agent 在多处实现中均正确遵守了这一约束。如果没有人在开始时明确这一原则，Agent 可能会将进度直接用 submission 分数计算，造成语义混淆。

### 3.2 视觉参考提供

Agent 将系统设计成了科幻风格（初版），而产品定位是真实赛马场。这一偏差只有在人工查看页面后才能被发现。人工介入提供了底图和配色方向，将实现导回正轨。

### 3.3 "使用体验"审查

字号偏小、赛道压到看台、Calibrator 与 Jumbotron 视觉不统一——这三个问题都是通过"实际打开页面看一眼"发现的，而不是通过代码 review。这说明对于 UI 类产品，**使用体验层面的审查不可替代**。

## 4. 遇到的错误与幻觉

### 4.1 数据幻觉（I-03）

Agent 生成了看起来合理但实际错误的控制点数组（右侧 x=1600 重复形成平直段），这类错误外表合法（TypeScript 编译通过），只有通过人工对比视觉效果才能发现。这是 Agent 最危险的一类错误——无法通过静态分析检测。

**应对策略：** 对于有多处来源的关键数据，建立自动一致性检查（比如写一个 test 验证 Calibrator 默认点与 JSON 文件一致）。

### 4.2 风格幻觉（I-01、I-05）

Agent 多次在没有明确约束的情况下，自行选择了偏科幻/技术感的视觉风格。第一次被纠正后，Calibrator 仍然重复了同样的错误。

**应对策略：** 建立视觉风格卡（color tokens、参考截图），在每次新建 UI 组件时附在 prompt 中，强制 Agent 参考。

### 4.3 工程偏差（字号）

CSS 字号不是幻觉，而是 Agent 的"默认偏好"（偏小的紧凑样式）。通过一次明确的纠正，Agent 能够系统性地修正所有实例。

## 6. 如果重来，会怎么做

1. **在 Calibrator 任务开始时**，在 prompt 中明确："控制点必须从 track.profile.json 读取，不得硬编码；视觉样式必须与 race-live-view.tsx 保持一致"。估计可以消除 I-03、I-05 两个干预事件。

2. **在视觉类任务开始时**，将参考截图和色号卡附在 prompt 中。估计可以避免 I-01 的返工。

3. **建立数据一致性自动检测**：`npm test` 中加一个断言，校验 `OVAL_POINTS === track.profile.json.centerline.points`。

4. **更早进行"使用体验"审查**：不等到完成后才打开页面，而是在第一个可视版本出来后立即检查字号、间距、视觉匹配度。
