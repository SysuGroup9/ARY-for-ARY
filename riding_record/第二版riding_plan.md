# ARY GRS 001 第二版 Riding Plan  2026-06-05

## 1. 账号体系

- Organizer（企业/老师）可创建账号
- User（参赛者）可创建账号

## 2. 赛事流程

### 2.1 创建（Create）

Organizer 创建 Race，提供赛事信息和相关数据。

### 2.2 披露（Disclose）

比赛相关信息公开，展示比赛列表，参赛者可查看并报名。

### 2.3 组织（Organize）

- 参赛者点击具体比赛，查看详细信息，自行选择报名
- Coach 提供所有组员信息
- 比赛过程中，组员通过 DC 进行协作

### 2.4 展示（Display）

**状态展示：** 报名中、比赛中、比赛结束

**规则展示：** 比赛规则全程展示

**成果展示：**
- 在 Organizer 规定的提交频率下，自动读取参赛者当前进度，展示排名
- 截止日期后，公布所有人的排名、老师回馈的亮点、评价

## 3. 信息安全：去中心化、去持久化

### 3.1 Organizer 测试数据安全

参赛者点击测试后，发送测试代码给 ARY。ARY 记录参赛者相关信息，将代码转发给 Organizer。Organizer 在自己环境中完成测试，将结果返回给 ARY，ARY 再将结果返回给对应的参赛者。

关键原则：测试代码不经过第三方，Organizer 在自己的安全环境中执行评测，ARY 只做中转，不持久化存储。

### 3.2 周期进度评价

ARY 自动读取参赛者代码和 Agent 对话记录，记录参赛者信息后，将代码发送给 Organizer。Organizer 在自己环境中进行进度评价，将结果返回给 ARY，ARY 记录进度并展示。

关键原则：周期性自动读取，无需参赛者手动触发，评价结果实时更新到榜单。

## 4. 核心原则总结

| 原则 | 说明 |
|------|------|
| 去中心化 | 赛事数据主权属于 Organizer，ARY 不存储完整 Race 数据 |
| 去持久化 | 参赛者代码仅在 ARY 中临时中转，评测完成后删除 |
| 数据安全 | 企业测试代码不离开企业内网 |
| 透明披露 | ARY 只展示 Organizer 主动披露的公开数据 |
