## I-01：初版科幻风格与产品定位不符

**发现方式：** 人工查看页面截图

**问题描述：**
Agent 初版 race-live-view.tsx 实现了深色科幻主题：
- 背景：深蓝色渐变天际线 + 星空粒子
- 赛道：荧光蓝/绿色渐变
- 马匹：赛博朋克风格标记

这与 ARY 的赛马场主题完全不符，给评审展示会产生错误的产品印象。

**干预过程：**
1. 用户提供实景赛场照片（`public/jumbotron底图.jpg`）
2. 明确指定配色：土黄色赛道 `#c4924a`、白色护栏、绿色内场
3. Agent 重构 SVG 渲染层（保留逻辑层不变）

**根本原因分析：**
Agent 在没有视觉参考的情况下，默认生成了与其训练数据中"赛车/电竞大屏"关联更强的科幻风格，而非真实赛马场风格。需要人工提供参考图作为设计约束。

**经验：** 涉及视觉风格的实现，必须在 prompt 中提供参考图或具体的色号/风格描述，否则 Agent 会基于其默认审美做出偏离预期的选择。

## I-02：赛道椭圆有裂缝

**发现方式：** 人工肉眼观察

**问题描述：**
放大赛道后，椭圆环内侧和外侧边界处可见 1 px 宽的白色裂缝，在深色背景映衬下尤其明显。

**技术根因（Agent 诊断）：**
```
原实现：
  <path d={outerD} fill="#c4924a" />  ← 外圆填充
  <path d={innerD} fill="#0a3707" />  ← 内圆覆盖（遮盖内部）

问题：两个路径在边界处重叠区域的抗锯齿计算产生半透明像素带（1 px）
     该半透明区域透出底层背景，形成"裂缝"
```

**修复方案：**
```svg
<mask id="trackMask">
  <path d={outerD} fill="white" />  ← 允许绘制区域
  <path d={innerD} fill="black" />  ← 抠洞（遮挡区域）
</mask>
<rect width="100%" height="100%" fill="#c4924a" mask="url(#trackMask)" />
```

单次绘制，无两层路径交界，彻底消除裂缝。

**验证：** 放大 400% 查看，边界处光滑无间隙。

## I-03：Calibrator 控制点与 Jumbotron 不一致

**发现方式：** 人工对比两个页面的赛道形状

**问题描述：**
`/jumbotron?raceId=race_jumbotron_demo` 展示的椭圆赛道与 `/jumbotron/calibrator` 点击"预设：椭圆"后的赛道形状明显不同：
- Jumbotron：平滑自然的椭圆
- Calibrator：右侧和左侧各有一段明显的平直段

**根本原因（Agent 调查）：**

Agent 在实现 Calibrator 时，OVAL_POINTS 数组是独立硬编码的，与 `track.profile.json` 中的点不同：

```typescript
// Calibrator 错误版本（右侧 x=1600 重复，形成平直段）
[1600, 540], [1600, 400], [1420, 280], [960, 250],
[500,  280], [320,  400], [320,  540], [320,  680],
[500,  800], [960,  830], [1420, 800], [1600, 680],

// 正确版本（来自 track.profile.json）
[1600, 540], [1514, 395], [1280, 289], [960, 250],
[640,  289], [406,  395], [320,  540], [406,  685],
[640,  791], [960,  830], [1280, 791], [1514, 685],
```

**干预过程：**
1. 人工发现形状不一致
2. 要求 Agent 调查根因
3. Agent 运行 `node -e "console.log(require('./Jumbotron/tracks/track.profile.json').centerline.points)"` 确认正确值
4. Agent 同步修复 OVAL_POINTS 和 RECT_POINTS

**经验：** 当多处存在同类数据（JSON 资产 + 代码硬编码）时，Agent 可能各自独立生成而不主动保持一致。需要人工建立"单一来源"规则，并在 review 时核查。

## I-04：控制面板字号过小

**发现方式：** 人工在屏幕上使用 Calibrator

**问题描述：**
右侧控制面板所有文本（标签、输入框、按钮、统计信息）字号仅 10–12 px，在普通显示器下勉强可读，在大屏演示场景下几乎不可辨识。

**干预：** 要求 Agent 将所有控制文本字号提升到 13–15 px。

**Agent 执行：**
- 系统性遍历 `calibrator.module.css` 所有 `font-size` 声明并提升
- 未遗漏任何边角（包括 `.hintBar`、`.stat`、`.validItem`）

**经验：** 可用性细节（字号、间距、对比度）需要人工在实际使用中发现，Agent 在生成 CSS 时倾向于偏小的值（符合"紧凑"的默认审美）。

## I-05：Calibrator 视觉风格与大屏不统一

**发现方式：** 人工对比两个页面

**问题描述：**
Calibrator 的 SVG 画布使用了深绿色主题（`#1a3a1a`、`#2d5a2d`），与 Jumbotron 的土黄色赛道 + 真实底图完全不同。如果在演示中前后切换，会给评审留下"这两个工具不是同一个系统"的错误印象。

**干预：** 要求 Calibrator 视觉风格与 Jumbotron 完全一致。

**Agent 执行：**
- 添加 `<defs>` 包含 mask、clipPath、晕影渐变
- 无用户上传时默认显示赛场底图（opacity 0.28）
- 土黄色 `#c4924a` 赛道面（同款 SVG mask 方案）
- 白色护栏（双层渲染）
- 琥珀 `#f59e0b` 检查点 + 圆柱端头

## I-06：赛道过大，压到看台区域

**发现方式：** 人工观察 Jumbotron 大屏

**问题描述：**
椭圆赛道左右两侧距离画面边缘仅 320 px，方形赛道 340 px。叠加 laneHalfWidth 75 px 后，外侧护栏实际在约 245–265 px 处，已进入背景照片中的看台观众区域，视觉上赛道"浮"在看台上方，失真明显。

**干预：** 要求缩小赛道。

**Agent 执行：**
- 以画面中心 (960, 540) 为锚点，按 0.80× 缩放所有控制点
- 数学计算正确，三处文件同步更新：JSON × 2 + calibrator-ui.tsx

**结果：**
- 椭圆：左右边距各 448 px（+128 px）
- 方形：左右边距各 464 px（+124 px）
- 外侧护栏距离画面边缘约 373–389 px，看台区域不再受影响

## I-07：Prisma 迁移后 TypeScript 类型错误

**发现方式：** Agent 主动运行 `npx tsc --noEmit` 发现

**问题描述：**
新增 `trackDirection` / `trackStartFinishS` 字段后，Prisma 生成的 `Race` 类型未更新，导致下游组件访问新字段时 TypeScript 报错。

**处置：**
```bash
npx prisma generate  # 重新生成 Prisma Client
```

**经验：** Prisma schema 更改后必须同步运行 `generate`；Agent 在此次会话中能够主动识别并执行，无需人工介入。

---

## 总结：人工干预的关键节点

在本次 Jumbotron/Calibrator 开发中，人工干预集中在以下三类场景：

1. **视觉决策**（I-01、I-05）：Agent 无法推断出符合产品定位的视觉风格，需要人工提供参考图或明确规格。

2. **跨文件一致性**（I-03、I-06）：Agent 在多处维护同类数据时可能独立生成，造成不一致。需要人工 review 时主动核查"单一来源"原则是否被遵守。

3. **感知类问题**（I-02、I-04、I-06）：裂缝、字号、尺寸是需要在实际使用中才能察觉的问题，Agent 无法通过代码分析主动发现，必须经由人工使用页面后反馈。
