# 小组分工记录

## 团队角色

| 角色 | 姓名 | 职责 |
|------|------|------|
| Coach（产品阶段） | 阮依成 | 产品定义阶段的技术/方法引导、PRD框架设计、PRD撰写、测试 |
| Coach（技术阶段） | 肖懿 | Demo实现阶段的技术引导、架构设计、测试 |
| Rider | 黄智亮 | 产品功能定义、PRD撰写、测试 |
| Rider | 陈怀容 | PRD框架设计、ARY要求审阅与检查、绘图 |
| Rider | 陈诗翰 | Co-riding、PRD审阅、测试 |

## 协作方式

采用 **轮值 Coach + 多人协作** 模式：
- 产品定义阶段：由阮依成担任 Coach，引导团队完成需求分析和 PRD 撰写
- Demo实现阶段：由肖懿担任 Coach，引导团队完成技术方案和代码实现
- 其他 Riders 在各阶段配合完成具体工作

## 各阶段分工

| 阶段 | 主要负责人 | 参与人 | 产出 |
|------|-----------|--------|------|
| 需求分析 | 阮依成、黄智亮 | 全体 | 产品功能定义 |
| PRD撰写 | 阮依成 | 黄智亮、陈怀容 | PRD.md（初稿） |
| PRD审阅 | 黄智亮 | 肖懿、陈诗翰 | 审阅意见 |
| PRD修订 | 阮依成 | 黄智亮、陈怀容 | PRD.md（终稿） |
| ARY要求审阅 | 陈怀容 | 阮依成、黄智亮 | PRD.md 最终检查 |
| PoC实现 | 肖懿 | - | 可运行项目 |
| 绘图 | 陈怀容 | - | 可视化结构图 |

## 关键协作节点

- **周五下午 A505 教室**：全体小组讨论，完成 PRD.md 最终定稿，同步小组分工
- **日常沟通**：使用微信群即时沟通，同步进度与问题
- **任务跟踪**：使用 GitHub Issues 跟踪待办事项

## 协作质量说明

1. **轮值Coach**：不同阶段由不同成员担任Coach，发挥各自专长
2. **分工明确**：产品定义由阮依成主导，技术实现由肖懿主导
3. **沟通高效**：定期会议 + 即时消息，确保信息同步
4. **相互审阅**：PRD 完成后由陈诗翰、肖懿审阅，提出修改意见
5. **质量把控**：陈怀容对照 ARY 要求检查 PRD 完整性
6. **过程记录**：本文件记录分工与协作过程，可追溯
